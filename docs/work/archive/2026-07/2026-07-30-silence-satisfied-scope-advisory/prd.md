# Silence the scope advisory once the PR body already satisfies it

## Goal

Make the tooling/generated scope advisory carry information. Today it fires on
every branch that touches a tooling/generated file, whether or not the PR body
already contains the section it is asking for, so `Review preflight: 0
failure(s), 1 warning(s)` is the steady state of a correct branch. A warning
count that never reaches zero trains the reader to skip warning counts, which
is the failure mode that matters — the next warning that does mean something
gets skipped too.

## Background

`main()` in `templates/scripts/sd-ai-command-pack-review-scope.sh:291-298`
returns from the advisory branch before `check_pr_body_scope` at line 300 ever
runs, so advisory mode never resolves a PR body. That is deliberate and
documented: `docs/SD_AI_COMMAND_PACK.md:1871-1877` promises advisory mode warns
"without contacting `gh` or a PR". The advisory was designed as an author-time
reminder for the window before a PR exists, and in that window it is correct.

The gap is the window after. Once the PR exists and its body carries the
section, the advisory has positive evidence available and ignores it. Observed
on PR #280: the enforcing run exited 0 with no failure, while the preflight kept
reporting one warning for the whole review cycle.

This is therefore a contract revision, not a defect repair. The documented
offline property is being traded for accuracy, deliberately.

## Requirements

- Advisory mode must stay silent when it has positive evidence that the PR body
  already contains a recognized scope section.

- Advisory mode must keep warning whenever it lacks that evidence: no PR yet,
  `gh` absent, `gh` disabled by `SD_AI_COMMAND_PACK_SCOPE_CHECK_GH`, no JSON
  parser available, or a PR whose body lacks the section. Absence of evidence is
  not evidence the body is fine — the reminder is the safe default.

- Advisory mode must distinguish the two remaining warning cases in its wording.
  "Add it before opening the PR" is wrong once the PR exists; that case needs
  its own message.

- Enforcing mode behavior must not change at all: the same inputs must produce
  the same exit status, the same failure messages, and the same warn-and-skip
  paths as before. This task must not turn any advisory case into a failure or
  any failure into a pass.

  One declared exception: a crashing `python3` or `jq` today aborts the script
  through `set -e` with the interpreter's stderr and no `error:` line. After the
  resolver split it becomes a named `fail`. Exit status stays 1. Nothing else in
  enforcing mode may differ.

- No test may invoke the developer's real `gh`. Advisory-mode tests that
  currently inherit the ambient environment must be pinned, and the
  `gh`-resolved cases must use the suite's `gh` stub. A body supplied through
  `SD_AI_COMMAND_PACK_SCOPE_PR_BODY` short-circuits above `gh`, so it cannot
  stand in for the resolved-body path this task exists to fix.

- The machine marker `sd-ai-command-pack-scope-advisory: ` must still be emitted
  on every warning path, because `checkScopeAdvisory` in
  `templates/scripts/sd-ai-command-pack-review-preflight.mjs:3466-3496` matches
  the marker rather than the human wording.

- The advisory must remain non-fatal. It runs inside `make check`; a `gh`
  failure, a network timeout, or a malformed response must not fail the gate.

- The advisory must also remain *bounded*. Non-fatal is not enough: the path
  from `make check` to `gh` is fully synchronous, so a stalled `gh` would stall
  the gate no matter how its exit status is treated. The advisory invocation
  needs an explicit time limit, and expiry must degrade to no advisory rather
  than to an error.

- Positive body evidence must win over every reason the resolver has to give up.
  A body supplied through `SD_AI_COMMAND_PACK_SCOPE_PR_BODY` that already
  contains the section must silence the advisory even when `gh` is disabled,
  which today's resolution order would otherwise report as unknown. That exact
  combination — disabled `gh` *and* a satisfying body — needs its own test; it is
  the only proof the reordering happened, and cases that hold one half each do
  not cover it.

- The documented contract must be updated in the same change, since the
  "without contacting `gh` or a PR" promise becomes false. The edit belongs in
  `templates/docs/SD_AI_COMMAND_PACK.md`; the root copy is regenerated by
  `make sync`.

- `templates/**` is the source of truth. Root `scripts/**` is a generated mirror
  regenerated with `make sync`, never hand-edited.

## Constraints

- Shipped payload changes, so `CONTRIBUTING.md:98-104` applies: same-PR
  `manifest.json` bump (98-99), plus the matching top `CHANGELOG.md` heading and
  the all-pass `docs/fleet/candidate-validation.json` enforced by the release
  payload gate (100-104). The bump and the heading are hand edits;
  `make release-prep` validates them and refreshes the ledger, it does not write
  them.
- The fleet rollout stays deferred by standing user instruction. This task ships
  to the pack only; no campaign work and no controller state changes.

## Acceptance Criteria

- [ ] With a scoped change and a PR body containing a recognized scope section,
      advisory mode prints no warning and no advisory marker, and exits 0. This
      is proven twice: once with the body supplied through
      `SD_AI_COMMAND_PACK_SCOPE_PR_BODY`, and once with the body resolved from a
      stubbed `gh pr view`. The second is the shipped path.
- [ ] With a scoped change and a PR body missing the section, advisory mode
      warns with PR-exists wording, prints the marker, and exits 0 — likewise
      proven on both the supplied-body and stubbed-`gh` paths.
- [ ] With a scoped change and no resolvable PR, advisory mode warns with the
      existing pre-PR wording, prints the marker, and exits 0.
- [ ] With no scoped change, advisory mode prints nothing, exits 0, and never
      invokes `gh` — proven with a stub `gh` that would leave a sentinel file if
      it ran. Empty output alone does not prove the zero-scope early return
      survived.
- [ ] Every existing enforcing-mode test in `tests/test_review_scope.py` passes
      unchanged, including the `required` gh-mode failures and the explicit-body
      accept/reject cases.
- [ ] Both copies of `SD_AI_COMMAND_PACK.md` describe the new advisory behavior
      and no longer claim advisory mode avoids `gh`, with the template edited
      and the root copy regenerated.
- [ ] No test in `tests/test_review_scope.py` or `tests/test_review_preflight.py`
      reaches a real `gh`. Every preflight test qualifies, not just the advisory
      ones: `run_install` writes `.sd-ai-command-pack/manifest.json`, which the
      classifier treats as scoped, so the whole suite needs a single pinned
      default rather than per-call-site edits. Each case then pins
      `SD_AI_COMMAND_PACK_SCOPE_CHECK_GH`, supplies a body, or stubs `gh` on
      `PATH`.
- [ ] A preflight-level test proves the end-to-end outcome: a scoped change plus
      a stubbed `gh` returning a satisfying body yields a preflight run with zero
      warnings.
- [ ] The advisory invocation carries an explicit timeout, and expiry produces no
      advisory rather than an error. Closed by inspection of the `spawnSync`
      options and the existing `result.error` guard; a behavioral test would have
      to stall a stub `gh` for the full timeout, which is not worth the suite
      time.
- [ ] `make check` exits 0, and a preflight run on this branch reports 0
      warnings once the PR body carries the scope section.
