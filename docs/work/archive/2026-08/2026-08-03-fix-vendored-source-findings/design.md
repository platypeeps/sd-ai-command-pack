# Design — vendored pack-source findings fix (0.64.1)

## Canonical facts (verified on HEAD 2026-08-03)

- **Two mirrored trees.** Shipped scripts exist in both `scripts/` and
  `templates/scripts/`, byte-identical. `install.py` reads from `templates/`;
  `scripts/` is the maintainer-gate copy. Verified identical for
  recovery-artifacts, work-loop, update-spec-kb, status. Any edit must be
  applied to both and left byte-identical (a lint/gate enforces the twin
  invariant).
- **Manifest vs provenance.** `manifest.json` has `version` + a 776-entry
  `files[]` array of **routing metadata only** (`platform, kind, source,
  target, install`) — NO hashes. SHA-256 hashes live in
  `.sd-ai-command-pack/provenance.json` (`files` = `[path, "sha256:..."]`
  pairs), the dogfood install's provenance, regenerated by `make sync`
  (install from `templates/`). Editing a shipped script changes its
  **provenance** hash, not any `manifest.json` entry; `manifest.json.files[]`
  only changes if files are added/removed (none here). So the release step
  regenerates provenance via `make sync`, and bumps `manifest.json.version`
  by hand.
- **Release path.** `make release-prep` runs `.github/scripts/prepare-release.py`
  then `make check`. `make generate` regenerates command surfaces +
  surface-check; `make sync` re-installs the dogfood copy from `templates/`
  (refreshing `.sd-ai-command-pack/manifest.json`) and refreshes the spec KB.
- **Version source of truth is `manifest.json` `version`.** `prepare-release.py`
  does NOT bump it — it *validates* a version gate: it diffs the current
  `manifest.json` against `base_ref:manifest.json` and, when the shipped payload
  changed, requires `version` to have moved (`_manifest_version`, L210-214,
  L232+). So the bump is a manual edit of `manifest.json` `version` → `0.64.1`;
  `make sync` then recomputes the SHA-256 hashes in
  `.sd-ai-command-pack/provenance.json` (NOT in `manifest.json.files[]`, which
  carries no hashes), and prepare-release passes the gate. The version string also appears in `.sd-ai-command-pack/manifest.json`
  (refreshed by `make sync`) and `docs/fleet/candidate-validation.json`
  (fleet evidence, refreshed by release-prep when stale) — do not hand-edit the
  generated copies.
- **Gate.** `make check` = `test lint audit full-check`. `test` runs the suite,
  fails on any local skip, combines coverage, enforces `--fail-under=100` on
  `install.py,installer/*`, then `check-shipped-script-coverage.sh` +
  `check-shipped-script-docs.sh`. `lint` = ruff + mypy (over `scripts` and
  `templates/scripts`) + node --check + shellcheck. `audit` = bandit + zizmor.

## Finding-by-finding approach

All fixes are local, behavior-preserving except where a fail-closed path is
explicitly added.

### 1. recovery-artifacts.py / work-loop.py — empty `except: pass`
**Structural fix, not a comment.** CodeQL `py/empty-except` (which runs on the
consumers via CodeQL Analyze) fires on a handler whose body is only `pass` — a
comment is not a statement, so commenting does NOT clear it. Replace the
try/except/pass with `contextlib.suppress(<Exc>)` around the guarded call (or,
where the block does real work in a sibling branch, add an actual handling
statement). `suppress` removes the empty handler entirely and reads clean to
both CodeQL and Copilot. Confirmed empty pass-only handlers: recovery-artifacts
L202, L207, L211 (atomic write fsync/replace cleanup) + the `_CleanupLock`
acquire/release blocks; work-loop L1143-1144 (`except FileNotFoundError:
pass` on unlink). The re-verify step enumerates the exact current set; convert
each genuinely empty one. Behavior is preserved (same exceptions swallowed).

### 2. recovery-artifacts.py / work-loop.py — `read_text` decode policy
The raw "missing `errors=`" finding is largely **moot**: these callsites already
pass `encoding="utf-8"` (recovery-artifacts L216, L969; work-loop L2293), so
there is no host-locale dependency, and adding `errors="strict"` is a no-op
(strict is already the default). Do NOT add `errors="strict"`. The only real
gap: invalid UTF-8 raises `UnicodeError`, which these callsites do **not** catch
(they catch only `OSError`), so a corrupt receipt/file escapes as an unhandled
`UnicodeError`. Decision for Phase A: either (a) **rebut** — leave as-is if an
unreadable receipt surfacing loudly is acceptable, or (b) **harden** — catch
`UnicodeError` alongside `OSError` (or `errors="replace"` where a lenient read
is correct) and add an invalid-UTF-8 test. Pick per callsite with evidence;
this is not a mechanical `errors=` add.

### 3. update-spec-kb.py — `file_ends_with_kb_copy_marker` full-file read
`return path.read_bytes().endswith(KB_COPY_MARKER_SUFFIX_BYTES)` (**L553**) reads
the entire file. (L559/L567 also call `read_bytes` but legitimately — writing
the marker and a full-content compare — leave them.) Replace with a bounded tail read: open in binary, `seek(-N,
SEEK_END)` where `N = len(KB_COPY_MARKER_SUFFIX_BYTES)`, read N bytes, compare.
Guard files shorter than N (seek from start / read whole small file). Preserve
the existing `except OSError: return False` behavior.

### 4. status.py — schemaVersion validation + symlink guard
- `collect_recovery` (helper import L1193, dict check ~L1226) already catches a
  broad exception tuple and rejects non-dict results. Add: after the
  `isinstance(classified, dict)` check, require
  `classified.get("schemaVersion") == SCHEMA_VERSION` and return
  `{"status": "invalid", ...}` on mismatch — fail-closed, matching the finding.
  **Confirmed feasible:** `classify_repository` stamps
  `{"schemaVersion": SCHEMA_VERSION, ...}` (recovery-artifacts.py L737-738), so
  the expected value is the helper's `SCHEMA_VERSION` (read it off the loaded
  module, do not hardcode). The design.md fallback to "required-keys only" is
  therefore NOT needed.
- Symlink guard: the helper is resolved via
  `Path(__file__).resolve().with_name(...)` and gated on `helper.is_file()`
  (L1196), which follows symlinks. Tighten to reject a symlinked helper,
  mirroring this file's existing idiom at L492-494
  (`X.parent.is_symlink() or X.is_symlink() or not X.is_file()`). **Note a
  second identical guard** at L800-801 (the work-loop helper import in a
  different function) — harden both for consistency. Low severity; installed
  helpers are real files, so this does not change the normal layout.

## Constraints / risks

- **Twin drift** is the main risk. Mitigation: edit one tree, copy the file to
  the other, `diff` to prove identity, before running the gate.
- **Coverage floors, not 100%.** The 100% `--fail-under` gate applies only to
  `install.py,installer/*`. Shipped scripts have per-file floors in
  `.github/scripts/check-shipped-script-coverage.sh` (overall 76; recovery-
  artifacts 80, status 80, update-spec-kb 83, work-loop 80). New branches
  (schemaVersion mismatch, symlink reject, short-file tail read, any UnicodeError
  handling) will NOT automatically fail the gate, so explicit unit tests for
  each new branch are required for correctness — do not rely on the gate to
  force them. Adding branches without tests could even *lower* a per-file % below
  its floor, so tests are doubly necessary.
- **schemaVersion is available** (`SCHEMA_VERSION`, recovery-artifacts L48 import
  / L737 stamp), so the schema fail-closed fix is implementable directly; the
  earlier "fall back to required-keys" option is dropped (it would not satisfy
  the AC's schemaVersion requirement).
- **No fanout.** 0.64.1 is released to pack main only; consumers are untouched.

## Rollback

Single feature branch; revert the branch. No consumer impact (no fanout).
Version bump is reversible pre-merge.
