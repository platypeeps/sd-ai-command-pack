# Implementation plan: housekeeping KB refresh must not block its own merge

Source of truth is `templates/`; `scripts/` and the per-platform skill copies
are regenerated. Never hand-edit a generated copy.

## 1. Writer: semantic idempotence

`templates/scripts/sd-ai-command-pack-update-spec-kb.py`

- [x] Add `managed_block_is_sufficient(current: str) -> bool`: markers present
      and correctly ordered, the span between them contains a line for which
      `_entry_ignores_kb` is true, and `_remove_unmanaged_kb_entries` finds
      nothing to prune outside the span.
- [x] `merge_kb_ignore_block(current, *, rewrite=False)`: when `rewrite` is
      false and the block is sufficient, return `(current, True)` unchanged.

      `ensure_repo_gitignore`, `ensure_gitignore`, `planned_ignore_file_state`,
      and `planned_gitignore_state` so dry-run and real run agree.
- [x] Add CLI flag `--rewrite-ignore-block` (default off) as a plain
      `parser.add_argument`, outside the mutually exclusive
      `--dry-run`/`--check` group, and pass it down every path.
- [x] Module docstring gains the ownership rule from `design.md`.

## Verification (named before the work)

Falsifiable check, run from a scratch git repo fixture:

1. Write a `.gitignore` containing the managed block with the **old** banner
   text and commit it.
2. Run the helper.
3. `git status --porcelain` must print nothing, and the helper must report
   `gitignore: present`.

Failure is any output from `git status --porcelain`, or a report state of
`updated`. This is the exact sequence from issue #432 steps 3-6, minus the
merge, and it is the automated regression test in step 4.

Scope check for the blast radius — the writer is vendored into every consumer,
so before claiming completion:

- `grep -rn "merge_kb_ignore_block\|kb_ignore_block" --include=*.py .` covers
  every caller (helper, installer, thin conversion, tests).
- `python3 -m unittest discover tests -v` for the whole suite, not only the two
  touched modules.

## Rollback

Single commit revert; no state migration, no consumer-side cleanup. A consumer
that already committed a rewritten banner is unaffected either way.
