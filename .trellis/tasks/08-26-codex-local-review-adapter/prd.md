# Add a codex adapter as the default local review lane, keeping prism and gito available

## Goal

Local review today runs prism and gito through OpenRouter, billed per token. The Codex CLI on a developer machine is logged in with a ChatGPT subscription and can review a diff with a JSON output schema, so the same second opinion can run at no marginal cost. Add a built-in codex adapter to the local review stage next to prism and gito: it hands codex exec the exact base and head the coordinator resolved, forces a structured answer through an output schema, and maps a missing or logged-out codex to unavailable so the run degrades to the other lanes instead of failing. Make codex the first built-in default while leaving prism and gito enabled, so the OpenRouter lanes remain selectable per run or required per repository.

## Requirements

- `scripts/sd-ai-command-pack-review-local.py` accepts `"adapter": "codex"` next to `prism`, `gito`, and `argv`, and the built-in defaults in both that script and `scripts/sd-ai-command-pack-review.py` list codex first with prism and gito still enabled.
- The codex lane receives the exact base and head the coordinator resolved and reviews only that range (branch delta) or the uncommitted working tree (worktree); it does not offer codebase scope.
- The answer is constrained by an output schema to the normalized finding shape (path, line, severity, summary, family); an unreadable answer is a `failed` attempt, never `clean`.
- A missing `codex` executable or a logged-out codex is recorded as `unavailable`, and the run continues on the remaining lanes.
- codex joins the substantive ensemble policy, and `--local prism`, `--local gito`, and `requiredProviders` keep the OpenRouter lanes selectable.
- A repository that ships its own `.sd-ai-command-pack/review.json` replaces the built-in defaults, so codex reaches such a repository only through an explicit entry; this repository's `.sd-ai-command-pack/review.json` lists codex first, ahead of gito.
- Under the `documentation`, `metadata`, and `low-risk` cheapest policies, a codex attempt recorded as `unavailable` falls through to the next cheapest eligible provider without changing the plan's shape or any receipt digest.
- codex runs with `project_doc_max_bytes=0`, so the reviewed checkout's `AGENTS.md` cannot instruct its own reviewer.
- A worktree-scope run whose content digest no longer matches the tree after the providers finish is rejected as invalid instead of producing a receipt.
- The single-provider cost policies -- the `<risk>-cheapest` family and `low-risk-successor` -- all fall through to the next cheapest eligible provider when their sole lane is unavailable.
- A `branch_delta` run whose tree moved off the requested head, or became dirty, while a tree-reading provider ran is rejected rather than recorded as an exact-head receipt.
- When the reviewed change edits an instruction surface codex loads -- its own dot-directory, or a `SKILL.md` it would discover -- the codex lane records `unavailable` with that reason instead of reviewing a change that can write into its context.
- `tests/test_review_stage.py` covers the schema seed, the answer parse, the clean answer, the missing binary, the logged-out binary, the invalid answer, the codebase-scope refusal, the cheapest-policy fallback, and the moved-tree rejection.

## Acceptance Criteria

- [ ] `make test` passes with the new codex cases.
- [ ] On this repository, `sd-ai-command-pack-review-local.py --scope changes --local codex` against a real change produces a receipt whose codex attempt is `findings` or `clean`, with the schema and answer files in the attempt directory.
- [ ] With `codex` removed from PATH, the same command records the codex attempt as `unavailable` and the receipt still carries the attempts of the remaining configured lanes (gito in this repository).

## Planning review ledger

- C-1 (medium, addressed): the acceptance criteria assumed prism runs in this repository; its `review.json` configures only gito. Criterion reworded to the remaining configured lanes.
- C-2 (high, addressed): "first built-in default" only reaches repositories without their own `review.json`; a live run here reported `requested local provider is unavailable or ineligible: codex` until the repository entry existed. Requirement added for the explicit repository entry.
- C-3 (low, parked): the logged-out exit code mapping (1 and 2 to `unavailable`) is covered by the fixture, not by a real logged-out codex. Owner: whoever first sees a logged-out run; trigger: a codex attempt recorded as `failed` with an authentication message in `stderr.txt`.
- C-4 (high, addressed; raised by the codex lane reviewing this change): `costTier: none` made codex the sole cheapest provider, so a machine without codex ran no documentation, metadata, or low-risk review at all. Fallback added in the execution stage, verified by `test_cheapest_policy_falls_back_past_an_unavailable_codex`.
- C-5 (high, addressed; codex lane): codex loaded the reviewed checkout's `AGENTS.md` above the review prompt. `-c project_doc_max_bytes=0` added; skills and MCP servers configured in the developer's own `~/.codex` still load and are outside this task.
- C-6 (medium, addressed; codex lane): worktree-scope receipts digested the pre-run tree while codex re-read the live tree. Post-run digest comparison added for every worktree run, verified by `test_worktree_review_rejects_a_tree_that_moved_during_the_run`.
- C-7 (medium, addressed; codex lane, branch-scope pass): the cheapest fallback keyed on the `-cheapest` suffix and so missed `low-risk-successor`, which selects a single provider the same way. Guard widened, verified by `test_low_risk_successor_falls_back_past_an_unavailable_codex`.
- C-8 (medium, addressed; codex lane, branch-scope pass): the post-run binding check covered only worktree scope, while codex reads the live checkout under `branch_delta` too. Generalized into `_reconfirm_tree_binding`, which re-runs the head and cleanliness checks after the providers finish; verified by `test_branch_review_rejects_a_tree_that_became_dirty_during_the_run`.
- C-9 (medium, addressed; codex lane, branch-scope pass): codex discovers skills under `.agents/skills` and the equivalent directory beneath its own dot-directory, in the directory it runs in, so a change adding a `SKILL.md` writes text into its own reviewer's context. Verified empirically: a planted skill in this checkout appeared in the lane's own skill catalog. A planted skill did *not* hijack a matching prompt, so the exposure is injected catalog text rather than instruction override, and codex ships no switch to disable discovery (`features.*` has no skills toggle). The lane now steps aside for exactly those paths, verified by `test_codex_lane_steps_aside_when_the_change_edits_its_own_skills` and `test_codex_instruction_surface_detection_is_narrow`.
- C-10 (high, addressed; codex and gito lanes, base-update pass): a fallback that completed still aggregated as `unavailable`. `_aggregate_outcome` scans the set of attempt statuses and the unavailable primary stays in `attempts`, so `{unavailable, clean}` returned `unavailable`, the receipt recorded a limitation, and the coordinator reported `local provider failure blocks remote routing` — the exact opposite of "degrades to the other lanes instead of failing". A completed fallback now marks the primaries it covered with `supersededBy`; they keep their status in the receipt but stop deciding the aggregate or denying confidence. Verified by `test_a_clean_fallback_reviews_the_change_instead_of_failing`, with `test_an_unavailable_lane_beside_a_running_one_still_limits_the_run` holding the boundary that supersession requires a fallback to have actually run.
- C-11 (high, addressed; codex lane, base-update pass): C-9's taint detection matched any `SKILL.md` below any `skills` directory, but codex reads only `.agents/skills` and the equivalent directory beneath its own dot-directory, relative to its `-C` root. This repository carries skills for Claude, for plugin payloads, and in template trees, so the default lane disabled itself for a large share of its own repository's changes. Narrowed to the two roots codex actually loads, verified by the extended `test_codex_instruction_surface_detection_is_narrow`.
- C-12 (high, addressed; codex lane, base-update pass): C-5 left the developer's `~/.codex/config.toml` in scope as "outside this task". It is not: `--sandbox read-only` bounds the shell but not MCP servers, whose credentials stayed live while the model read diff text it does not trust. The lane now passes `--ignore-user-config`; auth still resolves through `CODEX_HOME`, so a subscription login keeps working. Verified by the argv assertions in `test_codex_adapter_seeds_schema_and_reads_the_answer_file`.
- C-13 (high, addressed; gito lane, base-update pass): C-8's `_reconfirm_tree_binding` received `selected`, not the fallbacks that ran. When every selected provider was unavailable, the only provider whose findings the receipt attests to was the one never revalidated, so a checkout that moved during its run went undetected. Now reconfirms against every provider that executed.
- C-14 (medium, addressed; gito lane, second base-update pass): C-10's supersession excluded fallback ids from the paths it marked, so an *earlier* fallback that was itself unavailable stayed active and outranked the later one that succeeded. The loop only advances to a second fallback because the first was unavailable, so an earlier fallback sits in exactly the position a primary sits in. Everything unavailable ahead of the successful fallback is now covered.
- C-15 (medium, addressed; gito lane, second base-update pass): C-10 let a fallback clear the limitation of a provider named in `requiredProviders`, so a repository policy saying "this lane must run" could be overridden by the fallback list. Required lanes are never superseded; an unavailable one stays a limitation and the gate keeps reporting it. Verified by `test_a_fallback_does_not_cover_a_required_provider`.
- C-16 (medium, addressed; gito lane, second base-update pass): C-8's worktree reconfirmation compared only the content digest, recomputed against the refs the receipt names rather than the live checkout, so a HEAD that moved to a commit carrying an identical delta passed. HEAD equality is now checked first.
