# Add a codex adapter as the default local review lane, keeping prism and gito available

## Goal

Local review today runs prism and gito through OpenRouter, billed per token. The Codex CLI on a developer machine is logged in with a ChatGPT subscription and can review a diff with a JSON output schema, so the same second opinion can run at no marginal cost. Add a built-in codex adapter to the local review stage next to prism and gito: it hands codex exec the exact base and head the coordinator resolved, forces a structured answer through an output schema, and maps a missing or logged-out codex to unavailable so the run degrades to the other lanes instead of failing. Make codex the first built-in default while leaving prism and gito enabled, so the OpenRouter lanes remain selectable per run or required per repository.

## Requirements

- `scripts/sd-ai-command-pack-review-local.py` accepts `"adapter": "codex"` next to `prism`, `gito`, and `argv`, and the built-in defaults in both that script and `scripts/sd-ai-command-pack-review.py` list codex first with prism and gito still enabled.
- The codex lane receives the exact base and head the coordinator resolved and reviews only that range (branch delta) or the uncommitted working tree (worktree); it does not offer codebase scope.
- The answer is constrained by an output schema to the normalized finding shape (path, line, severity, summary, family); an unreadable answer is a `failed` attempt, never `clean`.
- A missing `codex` executable or a logged-out codex is recorded as `unavailable`, and the run continues on the remaining lanes.
- codex joins the substantive ensemble policy, and `--local prism`, `--local gito`, and `requiredProviders` keep the OpenRouter lanes selectable.
- A repository that ships its own `.sd-ai-command-pack/review.json` replaces the built-in defaults, so codex reaches such a repository only through an explicit entry; this repository's `.sd-ai-command-pack/review.json` lists codex first, ahead of gito.
- Under the `documentation`, `metadata`, and `low-risk` cheapest policies, a codex attempt recorded as `unavailable` falls through to the next cheapest eligible provider without changing the plan's shape or any receipt digest.
- codex runs with `project_doc_max_bytes=0`, so the reviewed checkout's `AGENTS.md` cannot instruct its own reviewer.
- A worktree-scope run whose content digest no longer matches the tree after the providers finish is rejected as invalid instead of producing a receipt.
- The single-provider cost policies -- the `<risk>-cheapest` family and `low-risk-successor` -- all fall through to the next cheapest eligible provider when their sole lane is unavailable.
- A `branch_delta` run whose tree moved off the requested head, or became dirty, while a tree-reading provider ran is rejected rather than recorded as an exact-head receipt.
- When the reviewed change edits an instruction surface codex loads -- its own dot-directory, or a `SKILL.md` it would discover -- the codex lane records `unavailable` with that reason instead of reviewing a change that can write into its context.
- `tests/test_review_stage.py` covers the schema seed, the answer parse, the clean answer, the missing binary, the logged-out binary, the invalid answer, the codebase-scope refusal, the cheapest-policy fallback, and the moved-tree rejection.

## Acceptance Criteria

- [ ] `make test` passes with the new codex cases.
- [ ] On this repository, `sd-ai-command-pack-review-local.py --scope changes --local codex` against a real change produces a receipt whose codex attempt is `findings` or `clean`, with the schema and answer files in the attempt directory.
- [ ] With `codex` removed from PATH, the same command records the codex attempt as `unavailable` and the receipt still carries the attempts of the remaining configured lanes (gito in this repository).

- C-30 (high, addressed; found by the lane reviewing itself, eighth pass): the independence step-aside was routed through `_run_provider`'s `unavailable_reason` and recorded as `unavailable` — a member of `TERMINAL_FAILURES`, indistinguishable from a missing or logged-out binary. It therefore denied confidence, degraded the remote gate, and made the controller report "local provider failure blocks remote routing" with `exactHeadReady: false`. Because the guard fires on exactly the paths this pack ships (`.agents/skills`, `.codex`), **any** change touching them could never reach a clean local review — including this task's own pull request, which edits `.agents/skills/sd-help/references/command-catalog.md`. Rounds 1–7 hid it: findings blocked first, and only a findings-free round exposed it. The step-aside now reports `skipped`, which `OUTCOMES` already carries and `TERMINAL_FAILURES` deliberately excludes, with the reason and a `declined` marker on the attempt. It is still listed in `confidence.limitations` so the receipt stays honest that fewer lanes read the change, and `_blocking_limitations` keeps the gate's `degraded` signal terminal-only, on both the fresh and the reused-receipt paths. Verified by `test_a_lane_that_declined_does_not_block_a_clean_review`, which fails against the pre-fix script. `test_an_unavailable_lane_beside_a_running_one_still_limits_the_run` was manufacturing its unavailable lane through the taint path; it now uses a genuinely broken one, which is what it was always about.
- C-31 (medium, addressed; gito lane, ninth pass): C-30's status change suppressed the fallbacks. The execution loop advanced to a fallback only while every attempt read `unavailable`, so once a decline reported `skipped` the loop broke on its first iteration and no substitute ran. A declined lane produced no review exactly as an unavailable one did, and the fallback is a different tool the reviewed change does not taint — it can read what codex would not. The loop now treats a decline like an unavailable, and `_mark_superseded_by_fallback` covers it on the same terms, so a fallback that actually reviewed the change clears the limitation. Verified by `test_a_declined_lane_still_lets_a_fallback_review_the_change`, which fails against the pre-fix script.
- C-32 (medium, addressed; gito lane, ninth pass): C-30 also opened a policy hole. `requiredProviders` says a lane must actually run, and `skipped` sits outside `TERMINAL_FAILURES`, so a required codex could decline and neither degrade nor block the gate — the same override C-15 refused when a fallback tried to stand in for a required lane. `_blocking_limitations` now takes the required set and treats a required lane's entry as blocking whatever its status, and the plan carries `requiredProviders` so a re-gated stored receipt reaches the same verdict from the receipt alone. Verified by `test_a_required_lane_that_declines_still_degrades_the_gate`, which fails against the pre-fix script.
- C-33 (medium, addressed; gito lane, tenth pass): C-32 added `requiredProviders` to the plan unconditionally, immediately above the comment explaining why optional plan keys are conditional — the plan is digested into `policyDigest` and that into the receipt identity, so emitting a key nobody opted into moves every existing repository's digests and invalidates cached receipts fleet-wide. The key is now written only when a required lane is configured, which is also when the gating semantics actually changed.
- C-34 (high, addressed; gito lane, tenth pass; user decision "Both"): codex shipped `enabled: true`, and a substantive review selects codex, prism, and gito as lanes rather than fallbacks — so nothing superseded an absent codex and `_aggregate_outcome` ranked its `unavailable` above the other lanes' `clean`. Every repository that had not installed codex therefore failed every substantive review, contradicting the PRD line the fallback test quotes ("a logged-out codex degrades to the other lanes instead of failing the run"). Two changes: codex now ships opt-in (`enabled: false`, in both the local stage's `_default_config` and the controller's own default, which the shared-configuration test compares — the controller's entry already carried a later `enabled` key that silently overrode a first attempt at this); and `_aggregate_outcome` no longer lets an *absent* optional lane decide the outcome when other lanes reviewed the change. Only absence is demoted — `unavailable` and `skipped`, never `failed` or `cancelled`, which mean a lane ran and went wrong; `test_provider_failure_is_distinct_and_local_policy_controls_gate` caught a first attempt that demoted malfunction too. Required lanes are exempt, as everywhere else. The reduced ensemble is not lost: it stays in `confidence.limitations`, drives the gate's `degraded` signal, and `confidence.granted` no longer follows `outcome == "clean"` alone, so a degraded run cannot vouch for an ensemble that was never assembled. Verified by `test_an_absent_optional_lane_does_not_fail_a_run_the_others_reviewed`, which fails against the pre-fix script.
