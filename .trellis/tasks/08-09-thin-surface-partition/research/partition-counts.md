install-time provenance receipt has no manifest row and is therefore
outside this inventory by construction.

## What this means for an actual consumer

The 593-file `repo-native` bulk is dominated by platforms **no fleet
consumer installs**. Per `docs/fleet/consumers.json`, all eight consumers
declare exactly `claude`, `gemini`, `github`, `opencode` (plus the always-
installed `shared` payload). A consumer's installed footprint today is:

| Platform | Rows |
|----------|-----:|
| `shared` | 82 |
| `claude` | 59 |
| `github` | 23 |
| `gemini` | 21 |
| `opencode` | 21 |
| **Total installed** | **206** |

Under the thin model that 206 partitions into 29 files a consumer keeps
(6 `consumer-config` + 23 `repo-native` `github` rows) and 177 files that
move machine-scope. The only `repo-native` slice consumers actually carry
is `github`, which is repo-native by construction: GitHub reads workflows
and prompts from the consumer repository itself.

## Regenerating

`make generate` writes the artifact (after command-surface generation,
which rewrites the manifest it reads). `partition-surfaces.py --check`
byte-compares against the committed file;
`tests/test_partition_surfaces.py` runs that check against the live tree,
so drift fails the normal test lane.
